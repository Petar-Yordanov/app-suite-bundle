# Arky 0.7.2 - MSVC build-failure corrections

Reported Windows errors:

1. `tests\archive_engine_tests.cpp(151): error C3530: 'auto' cannot be combined with any other type-specifier` (many subsequent errors)
2. `src\app\export_store.cpp(60): error C2027: use of undefined type 'QUrl'`

## Root causes and changes

- Windows SDK RPC headers may `#define small char`. The local variable `small` in the compression method tests therefore expands into an invalid declaration. Renamed the variable and all uses to `codecSourcePath`. Prior `NOMINMAX` protection does **not** prevent this macro.
- `QUrl` was forward-declared through Qt headers, but its methods (`isLocalFile`, `toLocalFile`) require `<QUrl>`. Added the direct include to `src/app/export_store.cpp`.
- Set the Xmake project version to 0.7.2. No unrelated archive behavior changed.

## Tests executed here

- GCC/C++20 archive-engine compile and full regression suite: PASS
- GCC/C++20 transfer-planning compile and tests: PASS
- Macro-injection compile and full archive-suite run with `-Dsmall=char`: PASS
- `scripts/source-check.py` Qt resource/QML bridge consistency: PASS

## Not verified

- Actual Windows MSVC build, Qt runtime and Windows Explorer integration cannot be executed in this environment; Windows build feedback is the final confirmation of the two reported errors.

## Windows commands

From a VS x64 Native Tools shell, in this project directory:

```bat
xmake f -p windows -a x64 -m release -y
xmake -r
xmake run Arky
```

If you only need to validate the desktop app target, you may use `xmake build Arky` before `xmake run Arky`; `xmake -r` builds every target, including the tests.
