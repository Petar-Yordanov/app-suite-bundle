# Arky 0.7.5 — Qt `slots` macro collision (MSVC C2513)

## Root cause

`src/app/archive_controller.cpp` named a local `QSemaphore` shared pointer `slots`.
Qt defines `slots` as a macro in normal Qt builds, so MSVC parsed an invalid
local declaration and all nested lambda captures failed. The cascading errors
from lines 252–282 stem from this single incompatible identifier.

## Fix

- Renamed the local `slots` variable and each lambda capture/reference to
  `batchPermits` in `ArchiveController::openUrl`.
- Added explicit `<memory>` and `<stdexcept>` includes to the controller source.
- Added source-check regression guards for Qt keyword macros as local variables
  and lambda captures in the controller.
- Updated project version to 0.7.5.

## Verification

- Portable archive and transfer-planning C++ tests: see TEST_RESULTS.md.
- Qt/QML source consistency check: see TEST_RESULTS.md.
- The Windows Qt GUI / MSVC build cannot run in this Linux container and is
  **not yet verified**; user only needs to run `xmake -r` and `xmake run Arky`.
