# Arky 0.7.3 — Windows native MIME compile fix

## Reported failures

- C3646/C4430 for `CLIPFORMAT` in `windows_virtual_mime.hpp`: the type is not available through the header's Qt include context. Replaced the two registered-format storage fields with `unsigned int` (Win32 API's return type).
- C2664 for `RegisterClipboardFormatW(CFSTR_FILEDESCRIPTORW)` and `RegisterClipboardFormatW(CFSTR_FILECONTENTS)`: the macros are narrow ASCII format-name strings. Switched to `RegisterClipboardFormatA`.

## Validation

- The existing archive C++ tests passed locally.
- The existing portable transfer-plan tests passed locally.
- QML source checker passed locally.
- Windows MIME test extended to assert that both registered formats are nonzero and distinct.
- Windows/Qt GUI compilation could not be run here; users only need to build and launch on Windows.

## Windows commands

```powershell
xmake f -p windows -a x64 -m release -y
xmake -r
xmake run Arky
```

The warning about `vs_runtime` being deprecated is not a build failure.
